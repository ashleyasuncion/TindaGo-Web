PROJECT OVERVIEW
--------------------------------------------------------------------------------
TindaGo is a mobile-first daily business companion for traditional sari-sari
store owners. Refactored from an item-by-item POS system to a daily awareness
tool based on interview findings. Three pillars: Stock Tracker | Daily Cash
Summary | Utang Notebook.

Originally built as "Sari-Sari Smart" (June–Aug 2026). Rebranded to "TindaGo"
on Aug 18, 2026.

─────────────────────────────────────────────────────────────────────────────

  something in Step 1 had to cancel and redo the entire process.

  data inconsistency (corrections haven't been committed yet).
- Added "← Back to Check Shelves" button on Step 2 that calls showStep(1).
- cancelRestock() no longer needs to revert corrections (they were never
  applied).

WHAT CHANGED (code):

  corrections are now only applied in completeRestock() before recording
  purchases.
- restock.js: completeRestock() — applies corrections to products then

- restock.js: cancelRestock() — simplified; no longer reverts corrections

V2.9 — BFCACHE STALE DATA FIX (WEB) — DONE
Date: Aug 20, 2026
Status: IMPLEMENTED + VERIFIED

PROBLEM:
- Chrome's back/forward cache (bfcache) restores frozen page DOM with stale
  data when navigating back. For example: deduct stock on product_detail.html,
  press Back → inventory.html shows old quantity because DOMContentLoaded
  does not fire on bfcache restore, so loadState() + render never re-run.
- Forward link navigations (e.g. Inventory → Debts → Inventory) always do
  a full page load, which is why the round-trip shows the fresh value.
- Only add_product.html had a pageshow listener (added earlier for its own
  bfcache issue). All other state-rendering pages were vulnerable.

SOLUTION:
- Added pageshow event listeners to all 7 state-rendering pages. When
  ev.persisted is true (page restored from bfcache), re-runs loadState()
  + applyTranslations() + the page's render function to refresh the DOM.

Pages patched:
  inventory.html   — loadState + loadInventoryCatFilter + renderInventoryCatFilters +
                     renderManageInventory + applyTranslations
  debts.html       — loadState + applyTranslations + renderManageDebts
  product_detail   — loadState + applyTranslations + renderProductDetail
  debtor_detail    — loadState + applyTranslations + renderDebtorDetail
  record_payment   — loadState + applyTranslations + renderRecordPayment
  reports.html     — loadState + applyTranslations + loadReportPeriod + renderReports
  expenses.html    — loadState + applyTranslations + renderExpenses
  (add_product — already had pageshow handler, unchanged)

WHAT CHANGED (code):
- app.js: added window.addEventListener('pageshow', ...) in each page's
  init branch, mirroring the existing add_product pattern

FILES AFFECTED:
  app.js

VERIFICATION:
- node --check app.js — clean.
